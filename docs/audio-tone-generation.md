# Генерация звука из сгенерированной программы

## Проблема

Нативный `AudioKit.AudioRenderer.write` по реальной сигнатуре принимает
`write(buffer: ArrayBuffer)` — сырые PCM-байты. Через `sdk.call` параметры
приходят только строками, а программы пишутся на языке VERA, в котором есть
только `int`, `number`, `boolean`, `string` и массивы/классы. Типа «байты» нет,
base64 из чисел построить нечем.

## Текущее решение

Бинарный параметр передаётся одной строкой: 16-битные знаковые сэмплы через
запятую (-32768…32767, 48 кГц, моно). Программа строит строку сама из `int`
(`ui.intToString` и конкатенация), адаптер разбирает её в `Int16Array`, отдаёт
`ArrayBuffer` в `write`.

```
sdk.call("AudioKit.AudioRenderer.write", ["buffer", "0, 9234, 0, -9234"], "onAnswer")
```

Адаптер (`VeraSdkBackend.ets`): `parseSamples` → `ArrayBuffer` → `write`,
ответ — число записанных байт (2 на сэмпл).

Общее правило для скилла (`vera-skill.txt`, без привязки к API): параметр с
бинарными данными передаётся одной строкой сэмплов через запятую.

Дополнительно у адаптера остаётся `frequencyHz` + `durationMs` (+ `volume`) —
он синтезирует синусоиду сам. Это отступление от сигнатуры, поэтому в скилле
про него ничего нет.

## Проверено (через probe)

- 4 сэмпла → `result=8` (2 байта на сэмпл).
- 100 сэмплов → `result=200`; 400 → `800`; 1000 → `2000`; 4000 → `8000`.
- Полные 14 400 сэмплов (300 мс, ~90 КБ) через `aa start` не проходят — это
  ограничение длины аргумента тестового канала, а не адаптера. Для проверки
  именно этого объёма нужен тест через сгенерированную программу: sdk.call
  может иметь свой лимит, который я пока не знаю.
- Пробелы после запятых нужны только для `aa start`, адаптер с ними и без них
  одинаково разбирает строку.

## Что ещё не проверено

- Звук на динамике: `write` возвращает число байт, а не то, что слышно. Нужна
  запись микрофоном или анализ формы волны.
- Лимит размера строки через `sdk.call` из реальной генерации.
- Скорость построения строки в интерпретаторе VERA для 14 400 сэмплов.

## Альтернатива (не сделано)

Примитив в самом языке: функция, которая кодирует массив сэмплов в base64 или
байты. Тогда адаптер остаётся честным к сигнатуре `ArrayBuffer` и строка с
запятыми не нужна. Цена: изменение компилятора и VM.
