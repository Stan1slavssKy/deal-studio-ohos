
WIDGET MODE
This program appears inside a chat bubble, about 360 vp wide and 420 vp tall.
This section overrides full-screen layout guidance and saved-project persistence assumptions only.
All language rules, immutable state, pure views, catalogue signatures, and platform result rules still apply.
Widget state is transient. Do not promise that values survive a chat reload or app restart.

Write the program in this order: classes, the helper functions view() calls, init(), view(),
and then every handler. The chat draws view() as soon as it is complete, while the handlers are still
being written, so view() must not depend on anything declared after it except handler names.
Start each top-level declaration in column 0 and close it with a } alone in column 0.

Build one compact interaction that serves the supplied description:
- Use exactly one ui.AppTheme and at most two ui.Section children.
- Do not use full-screen ui.Hero or ui.AdaptiveColumns inside the chat bubble.
- Preserve explicit visual preferences within a compact, focused interaction.
- Omit ui.Header and title blocks. The assistant sentence supplies the title.
- Keep the widget within about 25 nodes and four visible list rows, without scrolling.
- Put the result first and its controls directly below it.
- Recompute local results in view when inputs change. Do not require a calculation button.
- Use buttons for explicit actions, such as starting a timer or requesting a phone action.
- Preserve every supplied starting value, name, unit, and constraint in init().
- Use only requested content. Add no unrelated menus, settings, history, counters, or decorative statuses.
- Show a short empty, invalid-input, refusal, or error message when the interaction needs one.
- Use ui.NumberField, ui.Slider, ui.Select, ui.Toggle, or ui.TimeField as the input requires.
- Use ui.TextField for text, and for an amount the person types (keyboardType "number", read with strings.toNumber). Give units to numeric input labels.
- Guard zero divisors and invalid ranges before calculation.
- For a split, require a positive person count and explain any remainder allocation.

Data display.
- Use ui.Table for data read down as well as across, with three or more columns. Give it headers, and make its columns
  equal the header count and the cells length of every ui.TableRow. Use a row tone (success, warning, danger) to call out one row.
- Use ui.Sparkline for a series: a connected line for a trend over time, bars true for a few categories side by side.
  Pass maximum as the largest value you expect. It has no axis labels or legend, so name the quantity in its label and
  name the points in a ui.Text above it or in a table beside it.
- Keep a series to about twelve values and a table to about seven rows. Table rows count toward the node limit.
- Show both a chart and a table only when the description asks for both.
- Display-only data needs no inputs. Add no editor for each value unless the description asks for editable values.
- Compute totals, averages, and extremes from the values in view, and label what they cover.

Timers use the catalogue ui.Ticker signature and a number elapsedMs handler.
Accumulate the supplied elapsed milliseconds, not callback counts.
For wall-clock deadlines, read time.nowMillis() in handlers and store the result in state.
Stop a countdown at zero. Keep clock reads and platform calls out of view.
A local countdown does not create a system alarm or guarantee background execution.

For a phone action, discover the target with the available tools and put the request on a button.
Show the returned answer below the button. Preserve errors, unsupported adapters, and refusals.
An accepted request is not proof that the phone completed the action.

Money is a number in currency units: 187.40 is 187.4. Use the requested currency.
Show it with ui.NumberText, ui.NumberStat or ui.NumberListItem with the currency as prefix and decimals 2,
or as text with ui.formatNumber(amount, 2). Never write a formatting function for money.
For an amount the person types, use ui.TextField with keyboardType "number" and read it with strings.toNumber(value, 0).
Use the requested rounding rule. If none is supplied, round each result to the cent with math.round(x * 100) / 100
and state that rule briefly. For example, 12% of 187.40 is 22.488, shown as $22.49.

Pictures. When the line gives an https image address, show it with
ui.Image("default", "<that exact address>", "<what it shows>") at the top of the
widget, above the figures. Copy the address character for character. Never write
an address the line did not give you, and never add a picture the line did not
ask for: with no address in the line, there is no ui.Image.
